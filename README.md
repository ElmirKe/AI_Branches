# База данных и чистые SQL-миграции для древовидного AI-чата («Coconut Tree»)

Этот проект реализует базу данных для веб-сервиса с разветвляющимися диалогами с ИИ (Tree / Node Graph Chat).

---

## 🎯 Проблема и решение

### Проблема классических линейных чатов
В обычном линейном чате все сообщения хранятся непрерывной простыней. При решении сложных многошаговых задач (например, проработка 5 пунктов по очереди):
- Контекстное окно забивается промежуточными ответами;
- К 4–5 шагу модель начинает терять изначальный системный промпт и первые вводные;
- Тратится огромное количество токенов на повторную передачу нерелевантной информации из соседних веток.

### Решение: Древовидная структура нод
Каждое сообщение — это узел (нода) дерева с ссылкой на своего родителя (`parent_id`).
Когда пользователь находится в любой ноде и задает вопрос:
1. Запрос к БД находит **только прямых предков** от корня до текущего узла (через рекурсивный CTE `WITH RECURSIVE` или функцию `fn_get_branch_context`).
2. В модель отправляется **чистая линейная ветвь без параллельных тем**.
3. Параллельные ветки полностью изолированы друг от друга!

## 📐 Архитектура базы данных (PostgreSQL)

### 1. Таблица `conversations` (Общий чат)
| Поле | Тип | Описание |
|---|---|---|
| `id` | `UUID PK` | Уникальный ID чата (по умолчанию `gen_random_uuid()`) |
| `title` | `VARCHAR(255)` | Название чата («Значение давления») |
| `system_prompt` | `TEXT` | Базовый системный промпт чата |
| `default_model` | `VARCHAR(100)`| Идентификатор модели по умолчанию |
| `created_at` | `TIMESTAMPTZ` | Время создания |
| `updated_at` | `TIMESTAMPTZ` | Время последнего сообщения (обновляется триггером) |

### 2. Таблица `messages` (Сообщения-ноды)
| Поле | Тип | Описание |
|---|---|---|
| `id` | `UUID PK` | Уникальный ID ноды |
| `conversation_id` | `UUID FK` | Ссылка на чат (`ON DELETE CASCADE`) |
| `parent_id` | `UUID FK` | Ссылка на родительскую ноду (`NULL` для корня, `ON DELETE CASCADE`) |
| `role` | `VARCHAR(20)` | `'user'`, `'assistant'`, `'system'` |
| `content` | `TEXT` | Текст сообщения |
| `is_fork` | `BOOLEAN` | Флаг: открывает ли нода новую альтернативную ветку |
| `fork_point_id` | `UUID FK` | ID ноды-источника развилки |
| `branch_index` | `INTEGER` | Индекс ветки у родителя (0 = основная, 1, 2... = ответвления) |
| `depth` | `INTEGER` | Глубина в дереве (0 для корня, 1, 2... рассчитывается триггером) |
| `metadata` | `JSONB` | Токены, модель, температура, reasoning и т.д. |
| `created_at` | `TIMESTAMPTZ` | Время создания ноды |

---

## 🌳 Индексы и производительность

- `idx_messages_conversation_id` — выборка всех нод чата за $O(\log N)$.
- `idx_messages_parent_id` — поиск дочерних узлов (развилок).
- `idx_messages_conv_parent` — составной индекс для построения графа.
- `idx_messages_id_parent` — оптимизация для рекурсивного CTE (подъем по предкам).
- `idx_messages_metadata_gin` — GIN-индекс для фильтрации по JSONB-метаданным.

## ⚡ Автоматизация (Триггеры и функции)

1. **Триггер `trg_messages_before_insert`**:
   - Автоматически считает `depth` (`parent.depth + 1`).
   - Автоматически вычисляет `branch_index` (если на одного родителя создается второй ответ).
   - Автоматически выставляет флаги `is_fork = TRUE` и `fork_point_id = parent_id`.
   - Бэкенду не нужно вручную рассчитывать эти поля!
2. **Триггер `trg_messages_after_insert`**:
   - Обновляет `conversations.updated_at` при каждом новом сообщении.
3. **Хранимая функция `fn_get_branch_context(target_node_id UUID)`**:
   - Возвращает готовую цепочку от корня к целевому сообщению для отправки в LLM.
4. **Представление `v_conversation_tree_nodes`**:
   - Добавляет к каждой ноде `children_count` и флаг `is_leaf` для фронтенд-графа.

## 🚀 Быстрый старт

### Вариант 1: Запуск через Docker Compose (Рекомендуется)
Если на компьютере установлен Docker:
```bash
docker compose up -d
```
Это автоматически:
1. Поднимет PostgreSQL 16 на порту `5432` (`postgres:postgrespassword`).
2. Автоматически применит миграции `001`, `002` и сид `001_seed_pressure_chat.sql`.
3. Запустит легковесный веб-интерфейс **pgweb** на **[http://localhost:8081](http://localhost:8081)**, где сразу можно увидеть таблицы и выполнять запросы!

### Вариант 2: Запуск через скрипты миграций
В PowerShell:
```powershell
# Применить все миграции:
.\scripts\migrate.ps1 up

# Загрузить тестовый чат «Значение давления»:
.\scripts\migrate.ps1 seed

# Проверить выборку контекста для ИИ:
.\scripts\migrate.ps1 test

# Откатить миграции:
.\scripts\migrate.ps1 down
```

В Linux / macOS / WSL:
```bash
chmod +x ./scripts/migrate.sh
./scripts/migrate.sh up
./scripts/migrate.sh seed
./scripts/migrate.sh test
```

### Вариант 3: Запуск через сторонние инструменты миграций
Файлы миграций следуют стандартному формату `*.up.sql` / `*.down.sql` и совместимы «из коробки» с:
- **golang-migrate**
- **dbmate**
- **goose**
- **Flyway**
- Любым SQL-клиентом (DBeaver, DataGrip, VS Code PostgreSQL extension).

## 🧪 Пример из вашей схемы («Coconut tree»)

Сид-файл `seeds/001_seed_pressure_chat.sql` формирует следующее дерево:

```
[Чат: Значение давления]
 │
 ├── (Корень) №1. Что такое давление? (user)
 │     │
 │     └── #1. Давление - это сила действующая на площадь... (assistant)
 │           ├── [Ветка А] №4 Как она применяется в жизни? (user)
 │           │     └── #4. Оно применяется в ..... (assistant)
 │           │
 │           └── [Ветка Б] №2. А что такое гидростатическое давление? (user)
 │                 └── #2. Гидростатическое давление - это.... (assistant)
 │                       ├── [Подветка Б1] №3 Объясни подробнее формулу про.... (user)
 │                       │
 │                       └── [Подветка Б2] №5. Расскажи про атмосферное давление (user)
 │                             └── #5 Атмосферное давление это..... (assistant)
```

### Проверка изоляции контекста:
Если отправить запрос `SELECT * FROM fn_get_branch_context('...id ноды №3...')`:
В результат попадут **только 5 сообщений**:
1. `№1. Что такое давление?`
2. `#1. Давление - это сила...`
3. `№2. А что такое гидростатическое давление?`
4. `#2. Гидростатическое давление - это....`
5. `№3. Объясни подробнее формулу про....`

Ни ветка №4 (применение), ни ветка №5 (атмосферное давление) **не попадут** в контекст для ноды №3.
Цель достигнута!
